- 核对日期：2026-11-04
- 来源类型：公开 GitHub 仓库说明与目录页
- 用途：为 AutoDev 后续设计和实现提供可追溯的结构参考
- 状态：研究笔记；不是 AutoDev 规范或采纳决策

## 上游项目概览

上游把命令行 Agent 自动化组织成可插拔的本地中台：事件来源、Agent 执行器、人工通知通道和交付流水线通过插件扩展；内核负责规则匹配、队列/轮次、持久状态与流程推进。仓库 README 描述了事件进入、规则路由、Agent 单轮执行后退出、必要时等待人工决定、收到回复后续跑的端到端路径。

## 仓库结构观察

以下目录职责根据上游仓库 README 的链接名称及目录布局归纳。具体模块边界、调用关系和实现细节需在设计或编码时打开对应上游文件核实。

| 上游路径 | 从结构可见的职责 | AutoDev 可参考的问题 |
| --- | --- | --- |
| `kernel/` | 自动化核心逻辑 | 将确定性调度和状态推进放在哪里、如何保持可重放 |
| `protocol/` | 内核与插件间的协议 | 阶段输入输出是否需要稳定、可校验的边界 |
| `cli/`、`bin/` | 命令行接口与可执行入口 | CLI 是否只调用统一流程服务 |
| `host/`、`worker/` | 宿主运行和任务执行 | 编排器与执行 Agent 的生命周期如何隔离 |
| `plugins/` | 可替换的事件、Agent、通知或交付扩展 | AutoDev 当前是否需要插件化，哪些接口应先保持简单 |
| `skills/agent-autoloop/` | Agent 侧流程协作说明 | 何种约定适合放在角色提示和项目规则中 |
| `sim/`、`tests/` | 模拟和自动验证 | 崩溃恢复、重复事件等状态边界如何验证 |
| `docs/`、`examples/` | 文档及场景配置 | 如何把抽象机制与可读场景示例对应起来 |

## 流程机制摘录

上游 README 所述路径可概括为：

1. 外部或定时事件被转换成标准事件。
2. 本机规则选择 Agent、工作目录及处理方式；重复到达的事项可以合并或排队。
3. Agent 完成一轮后退出，把结果写在最后一条回复中。
4. 只有需要用户决定的情况才创建等待项；等待期间不保留 Agent 进程。
5. 用户回复后恢复原任务上下文继续处理。
6. 对可自动完成的工作可安排延迟复查；流程深度设限以避免无界递归。

README 还介绍了追加式事件记录、状态索引、事务写入、输入与控制字段分离等内核设计。这里仅记录为上游自述的机制；其可靠性和适用性不能只由 README 宣称证明，需查看实现、测试与安全边界。

## 与 AutoDev 当前设计的关系

AutoDev 已在设计中选择需求驱动的九阶段流水线、确定性程序编排、状态落盘、文件式人工决策，以及角色与 Agent 解耦（详见 `docs/DECISIONS.md` 和设计文档）。因此，本资料主要用于检查 AutoDev 的阶段接口、执行器边界、恢复语义、人工等待、事件记录和验证覆盖。

候选借鉴点：

- 把流程推进与 Agent 生成内容分开，阶段迁移由可检查的程序条件控制。
- 将 Agent 单轮执行建模为可退出、可恢复的任务边界。
- 以结构化、持久化的人工决定连接暂停与继续。
- 用明确的轮次或深度上限约束自动递归。
- 通过模拟或故障注入检查重复输入、中断和恢复场景。
- 把集成点的扩展性放在明确需要之处，先评估 AutoDev 单项目、少数 Agent 场景的实际成本。

不应直接照搬的部分：

- 上游的事件插件中台和较宽的通知/交付插件面；AutoDev 当前范围更窄，是否需要由需求和成本决定。
- 上游的规则热加载、轮询或公网回调等运行机制；AutoDev 是否采用取决于其本地进程与 UI 设计。
- 上游关于零依赖、行数、性能、可靠性的自述数值；需对照对应代码、测试和运行环境重新验证。

## 后续核对清单

在 AutoDev 进入实现前，可针对以下问题打开上游具体源文件并记录核对结果：

- `kernel/` 与 `protocol/` 中的状态模型、事件格式和状态迁移规则。
- 事件日志与派生状态的原子写入、重建以及版本演进方式。
- Agent 会话续接所需的标识、输入输出和失败处理。
- 外部事件文字与本地控制配置如何分离和校验。
- 插件加载权限、工作目录边界、命令参数传递及交付安全。
- `sim/` 和 `tests/` 是否覆盖中断、重放、重复提交及人工等待恢复。

核对后如要改变 AutoDev 的方向、架构或安全约束，先更新 `docs/DECISIONS.md`，再更新相关设计文档；不要只修改本参考笔记。
