# 本机 Agent 与模型能力注册表

日期：2026-11-08。状态：已实现注册表读取与能力校验、默认值迁移及既有调用入口接入，验证见第 8 节。D021 记录依据；[教学样例](../config/agent-registry.example.toml) 默认禁用，运行配置为 config/agents.toml。

## 1. 目的与既有资产

登记本机有哪些执行器、它们能够调用哪些模型，以及模型适合/不适合哪些任务。选择先满足任务能力，再兼顾默认值、成本和 D019 的审查独立性；不单凭参数量决定能力。

实施前的 config.yaml 已有 agents/roles/limits，agents 项把执行器、厂商与模型组合在一起；cockpit.agents 用固定格式正则解析。原 requirements.llm_provider 加载时先加入 BUILTIN_FALLBACK_SPECS，配置读取失败也会退回内置列表，不能保证“只选择本机登记模型”。第一版已迁移这些配置并移除内置备用，复用其 ModelSpec/调用适配器和既有角色默认值，不另建执行引擎。

本轮只读检查在 PATH 找到 claude、codex、agy、ollama 的可执行文件；这不证明登录有效、模型已安装、服务在线或某种任务能力合格。本轮未调用模型、未读取密钥，30B 本地模型仍是用户提出的可能场景。

## 2. 文件位置与唯一来源

建议真实机器配置放在 workspace/agent-registry.toml（实施时纳入 gitignore），可通过显式路径选择；可分享的模板放 docs/config/agent-registry.example.toml。格式使用标准 TOML，避免把嵌套能力列表塞进现有固定格式 YAML 正则。位置和格式为本轮设计提议。

注册表被启用后，Agent、模型与能力只从该文件选择；config.yaml 的角色默认值和模型条目迁移或引用注册表，不维护两份相互独立的完整模型真源。迁移前 config.yaml 仍是现有运行配置，本样例不参与运行，不改变当前服务。

不因新注册表缺条目、禁用或解析失败，就从代码内置列表补回隐藏模型。旧 cc/codex 等用户输入代号可以兼容映射到登记 ID，但映射结果必须存在于当前注册表且满足所需能力。

## 3. 登记内容

| 对象 | 字段与含义 |
| --- | --- |
| 机器 | schema_version、machine：标识格式与本机，不能把另一台机器的可用性自动继承过来 |
| Agent 执行器 | 稳定 ID、名称、adapter、executable、enabled、availability；说明命令入口和支持的调用模式 |
| 模型 | 稳定 ID、vendor、name、完整 model_id、agent 引用、调用模式、推理档位（适用时）、enabled、availability |
| 能力与限制 | supported_tasks、unsupported_tasks、unverified_tasks：已登记支持、明确禁止分配、尚待验证；再配能力说明、证据引用与核对时间 |
| 凭证 | auth.type 为 cli_login / environment / none；environment 模式只记录 api_key_env 的变量名，必要时另记非敏感服务地址 |
| 默认值 | 各角色/阶段的默认 agent、model、调用模式和适用推理档位；引用登记 ID，不重复填写厂商和完整模型 ID |

调用方式由受控 adapter 和参数构造器解释，命令以参数数组执行，不把配置拼成任意 shell 字符串。模型的 CLI/API 入口、是否支持会话续接、文件/工具操作要分开说明；有文本输出能力不代表具备代码编辑或工具调用能力。选用的 Agent 也必须支持该步骤的读写与结果协议。

supported_tasks 是项目可用于选择的能力声明，必须说明证据；它不是模型永远不会犯错的保证。unsupported_tasks 是任务分配约束；unverified_tasks 不自动视为已支持。三者不应重叠。复杂度只作为补充说明，不能用“30B=弱、云模型=强”的粗略标签代替具体能力与验证。

例如，本地模型可以经验证后只登记文本分类、字段提取；把架构设计、代码审查、跨模块编码列为不适用。还未试过的任务应写未验证，不把模型天生做不到写成无证据的科学结论。

availability 区分 unknown / installed_only / verified / unavailable，并记录检查证据和时间；enabled 是操作者是否允许选择，二者不同。可用性会过期，调用失败仍按现有错误与恢复机制处理。

## 4. 默认值与选择规则

建议按以下顺序解析候选：本次明确指定 → 当前任务已保存的有效选择 → 对应角色/阶段默认值 → 本机全局默认值（若配置）→ 明确配置的合格备用候选。未指定不等于随机选型。

“从前面带过来”包括创建时继承项目/角色默认值、恢复时沿用本任务快照；不是让所有阶段机械继承上一阶段作者的模型。S3 等审核步骤优先用其自己的审核默认值，再按 D019 和实际可用能力降级。跨阶段保持需求/设计版本关联，模型会话是否能续接取决于适配器，不强行跨模型复用 CLI session_id。

任何候选都必须重新符合 enabled、本机可用性、Agent/模型调用兼容性和本任务能力要求。显式指定一个被禁止执行该任务的模型不能被静默接受；默认值失效或自动降级时说明原因和最后选择。记录有效配置快照与来源，配置变化不静默更换已在执行的任务。

D019 允许降低审核独立性或简单复用免审，不等于允许把复杂工作强行交给声明不支持的模型。如果缺审核者可单模型/工具检查继续；如果现有唯一模型不能完成核心任务，应说明能力缺口，不能假称该任务已有合格执行者。优先复用可用工具和已验证资产。

## 5. 凭证与本地模型

配置可没有 key 字段。CLI 登录态由现有工具管理；需要 API 凭证时只保存如 LOCAL_MODEL_API_KEY 的环境变量名，真正的值仅在执行边界读取并交给指定适配器，不展开到提示词、参数日志、产物或配置快照。环境变量名也不是凭证值。

无鉴权本地服务可明确 auth.type=none；不把不存在的 key 当成必填。环境变量缺失时报告变量名与无法调用，不打印其值。服务地址、模型 ID 和调用协议必须来自实际配置，不能仅因发现 ollama 可执行文件就猜测其服务或模型清单。

本地 HTTP/其他调用适配器、真实模型清单和能力验证尚未选择或实现；样例不登记假想的 30B 模型为已可用，也不调用外部服务来探测。

## 6. 实施接缝与验收建议

实施范围需要覆盖：cockpit.agents 的配置读取、driver.setup 的 autoloop 规则生成、Controller/handoff 的角色解析、requirements.llm_provider/agent_runner、兼容 agent.load_settings/worker、Web 配置与模型选择、飞书模型选择，以及对应调用者和测试。选型统一、执行适配继续复用，角色上下文与权限不因注册表而放宽。

先完成字段/验证器与旧配置迁移，固定当前默认角色；再让所有入口使用同一解析结果，消除未登记的内置备用；最后在假 Agent/假本地服务上验证默认继承、跨角色独立选择、禁用/缺模型/能力不足、缺环境变量和不泄漏凭证，回归原有流水线与两套需求入口。未经真实试用不把能力标成 verified。

本轮样例仅做 TOML 语法、引用和不含凭证值检查。尚未实现选择器、真实机器注册文件、API 适配器或能力探测；不改变运行配置，不重启服务。

上段为设计阶段的验证边界；实际实现进度以第 8 节为准。

## 7. 当前实施计划

用户已授权先固定本方案并合入 main，再开始实现。按三个小步推进：注册表读取/校验与旧配置迁移；统一各调用入口的模型与默认值解析；假 Agent、默认继承、能力拒绝与凭证边界测试及文档收口。每步同步 next/changelog 并提交；注册表完成后以 PR 合入 main，再进入设计机器人的应用层与渠道接线。不会因实施配置而改 autoloop 内核或启动真实模型。

现有完整模型 ID 和角色默认值必须保留，旧会话快照继续兼容；对模型能力采用已有证据和明确标注的未验证项，不凭参数量自动推断。配置或凭证不合格时返回可操作错误，不静默启用隐藏备用模型。

第一步实施细化：随仓库提供 config/agents.toml 作为可迁移的既有配置目录，本机 workspace/agent-registry.toml 或 AUTODEV_AGENT_REGISTRY 指定文件整体替代它（不叠加隐藏条目）。config.yaml 保留项目/轮次设置，通过 agent_registry 引用注册表；角色默认值迁入注册表，Web 的角色修改可写为 config.yaml 项目覆盖引用。旧式 agents/roles 配置保留解析兼容，但不补入任何内置模型。注册表相对路径按 AutoDev 安装根解析，与旧文本解析器的输入方式兼容。

先复用现有 Claude/Codex/agy 参数构造，增加仅文本的 ollama CLI 接口以承载未来本地小模型；不实现通用公网 HTTP API，也不猜测或下载本地模型。凭证在进程启动边界验证，接口返回元数据而不返回值。流水线角色仍需其执行器具有现有文件/产物协议能力，不能将仅文本模型直接当作编码执行器。

## 8. 第一版实现与使用

- 运行登记在 config/agents.toml，现有模型 ID/角色默认值已迁移；config.yaml 保留项目/轮次及注册表引用。workspace/agent-registry.toml 已忽略提交，或用 AUTODEV_AGENT_REGISTRY 显式指定整份机器配置；不混入内置模型。
- cockpit.registry 验证引用、可用状态、能力集合与凭证字段，提供 select 的明确指定/任务已有选择/角色默认值顺序。当前尚未实现自动寻找备用或能力评分；D019 分级执行仍是设计机器人下一步，不在注册表读取中偷偷降级。
- cockpit.agents 统一解析默认角色，Controller/handoff/规则生成及 Web 保存检查所选能力；旧 agents/roles 文本仍可读。Web 角色修改只保存登记 ID 引用，保持乐观锁。
- requirements.llm_provider 不再补入 BUILTIN_FALLBACK_SPECS，显式空注册表也不会回退；Web/飞书、两套需求入口继续复用其选择结果与现有执行器。旧持久化会话保留原配置快照，不自动改写。
- 单模型元数据返回支持/禁止/未验证任务和说明。Ollama 适配仅支持无状态文本，已用假进程验证输入/输出；不登记或下载假想本地模型，不承诺工具或代码文件执行能力。
- CLI/API 需要的凭证在调用边界从环境验证，快照只存变量名；现有 CLI 登录态继续使用。autoloop 内置适配器仍依赖标准 CLI 名称，自定义 executable 仅适用直接/文本调用，不伪称支持完整流水线。
- 验证：309 项 unittest（新增 12 项注册表/能力/默认值/凭证/本地假进程/旧配置兼容检查）通过；版本化需求隔离中台假 Agent 集成、完整 S1～S9 假 Agent 联机回归通过。未调用真实模型、未发送消息、未重启部署服务。
