## 3. 地基的位置

- 现在的检出在 `/tmp/autoloop-spike/home/app`，重启后会丢。融合前要固定一个位置，例如仓库外的 `~/code/agent-autoloop`，并锁定提交 `8f8e2ee`。
- 不改上游内核。它的 `AGENTS.md` 写明内核是纯函数，由 `tests/purity.test.ts` 守着。我们的东西放在它外面：规则文件、插件、外部程序。
- 只有确认外面实现不了时才考虑 fork，并先在 `docs/DECISIONS.md` 记原因。
- 风险：单人维护的新项目，许可证是 MIT；要求 Node 24，本机是 24.10.0。

## 4. 目标结构

```
        你（命令行 / Web / Herdr 窗格）
                    │ 同一份数据：中台的 /v1/state 与事件日志
                    ▼
   ┌────────────────────────────────────┐
   │ agent-autoloop 中台（地基，不改）     │
   │ 事实日志、队列、租约、重试、卡片、去重   │
   └──────▲──────────────────┬──────────┘
          │ emit 事件         │ 领活（worker）
   ┌──────┴────────┐   ┌─────▼───────────┐
   │ 流水线驱动      │   │ Agent 进程       │
   │（我们的，Python）│   │ claude -p / codex │
   │ 阶段、轮次上限   │   │ exec / agy -p     │
   │ 厂商不同、产物校验│   └─────────────────┘
   └───────────────┘
```

- 中台管"可靠地把活交给 Agent 并收回结果"。
- 我们的流水线驱动管"下一步做什么"，仍由确定性程序决定（D004），Agent 不决定流转。
- 界面是中台数据的客户端，不是流程的一部分，关掉不影响流程。

## 5. 融合步骤

每步独立计预算，关键项先跑，不让一项耗尽另一项（L002、L006）。每步通过才进下一步，不通过先回改本文。

| 步骤 | 做什么 | 通过标准 |
| --- | --- | --- |
| F0 | 固定检出位置与提交；把冒烟测试写成可重复的脚本放进 `tests/` | 一条命令跑完冒烟，输出通过或失败，不留残余进程和端口 |
| F1 | 真实 Agent 无界面：规则里配 Claude、Codex、agy，模型一律写完整 ID（`docs/MODELS.md`） | 各跑一轮写文件的任务；日志里的实际模型名与配置一致；权限不弹窗卡住 |
| F2 | 流水线驱动：用 Python 标准库经 `emit` 或 `POST /v1/events` 发事件，经 `/v1/stream` 得知一轮结束，再校验产物 | S1 到 S3 跑通，REWORK 回路有轮次上限，作者与审查者厂商不同时才放行 |
| F3 | 界面：命令行（Herdr 窗格里看）与 Web，读同一份中台数据 | 两个界面同时开，显示一致；关掉任何一个不影响流程 |
| F4 | 模板：角色模板和规则从一处生成 | 改一处模板，`check` 通过，新一轮用新模板 |
| F5 | 崩溃与卡住：强杀中台、强杀 worker、Agent 超时、权限弹窗 | 恢复后不重复、不丢；卡住的被判出来并给出处理 |
| F6 | 清理：驾驶舱里不再需要的窗格驱动代码移除，文档回写 | 测试通过，`docs/INDEX.md` 与 `next.md` 同步 |

### F0、F1 的通过标准

判定靠命令和文件，不靠 Agent 自述。每格只有通过、失败、未验证三种值，附证据路径；读不出来的记未验证，不算通过。

F0（`python3 -I tests/smoke_autoloop.py`，退出码 0 为通过，共 10 项）：锁定提交、`init`、监听、`doctor` 在线、`emit` 被接住、第 1 轮有领取和结束、重复 id 不产生第 2 轮、端口释放、进程退出、真实数据目录与技能链接未被动过。指向不存在的检出目录时必须失败（已验证退出码 1）。

F1，Claude、Codex、agy 各跑一轮"在临时目录写指定内容的文件"，同时满足五条才算通过：
1. 这一轮正常结束，第一行不是"没跑成"或"待你处理"。
2. 文件存在且内容完全一致，直接读文件。
3. 日志里的实际模型名等于配置里的完整 ID。Claude 另做对照：两个不同的完整 ID 必须得到两个不同的实际模型名。
4. 没有被权限确认卡住，在超时内结束。
5. 有用量或费用记录。

反向探针：让 Claude 执行一条未放行的 Bash 命令，拒绝可以接受，挂起算失败。

结果：全部通过则进 F2；有失败先停下看原因；需要放宽权限（如 `bypassPermissions`）的，先问用户；agy 失败不阻塞另两条线，如实记录。

### F1 要先查清的事

- Claude 用 `-p`，上游适配器的权限映射是 `read` 对应 `plan`、`edit` 对应 `acceptEdits`、`full` 对应 `bypassPermissions`。`acceptEdits` 下 Bash 不会被放行，而我们两次卡住都是权限弹窗；无界面模式遇到要批准的操作是拒绝还是挂起，没实测。
- Codex 用 `exec`，启动参数带 `approval_policy="never"`，不会弹确认。
- agy 没有专用适配器，只能走 `use: "command"`。协议文档只写了 `{prompt}` 占位符，`{model}` 是否支持没核实；不支持就把完整模型 ID 写死在命令里。
- 规则里的 `model` 若写别名，会撞上 magpie 映射。F1 开头先做 G3-0：同一 CLI 用两个完整 ID，确认实际模型不同。

### F2 的接口，还没验证

- 外部驱动发事件、等结束。v2 报告里"方式 A：外部推进"已经通过，但当时是用 shell 脚本等待；用 `/v1/stream`（SSE，只认本人密钥，`after=N` 续读）判断某一轮结束，没试过。
- 产物契约：上游的回执是 Agent 最后一条消息，不检查产物文件。我们的 `done.json` 与产物校验留在驱动里做（`pipeline.py` 的 `validate_done` 可复用）。
- 阶段状态放哪里还没定，见第 9 节。

## 6. 界面：命令行和 Web 共用一份数据

上游明确"中台没有界面"，但留了两个只读口子，本人的密钥可用：

- `GET /v1/state`：总览（在线情况、卡片、运行中和最近的轮次）。
- `GET /v1/stream?after=N`：SSE，推送事实日志，断线可从序号续读。

建议：
- 命令行（放在 Herdr 窗格里）和 Web 都只做这两个口子的客户端，不各存一份状态。两边显示不一致就是客户端的 bug。
- 命令行先做：复用现有 `status` 的思路，加一个持续刷新的视图。Herdr 窗格只是显示位置，窗格丢了不影响流程，这正好解决"窗格会死"的问题。
- Web 后做，沿用 D010：只监听 127.0.0.1。本人密钥只放在服务端，不下发给浏览器。如果以后要从手机访问，必须先加认证再开放，现在不做。
- 我们的阶段、轮次、厂商检查结果由流水线驱动写进自己的文件，界面同时读中台数据和这些文件。是否也写回中台（例如用事件），见第 9 节。

没验证：`/v1/stream` 的事实 JSON 字段是否足够画出实时视图，需要在 F3 开头先接一次看实际数据。

## 7. 模板与定制

- 规则（`rules.json`）里每条有 `to`、`cwd`、`skill`、`prompt`、`emits`、`parallel` 等字段，这是上游给的定制点；规则改动几秒内生效，写错了旧规则继续跑并推卡片。
- 我们的角色模板（`templates/roles/<role>.md`，设计 7.1 节）对应规则的 `prompt` 或 `skill`。`skill` 如何解析、放在哪个目录，我只读到字段名，没核实，F1 开头确认。
- 外部文字（事件的 `detail`）按上游规则不进提示词，只进标明"是资料"的文件。我们的需求正文走这条路，不能直接拼进提示词。
- 不做规则生成器。先手写 `rules.json`，等出现重复到难维护时再说。
