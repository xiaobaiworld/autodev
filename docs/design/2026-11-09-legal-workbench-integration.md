# 法律工作台：需求到设计原型整合测试

日期：2026-11-09。状态：真实模块整合测试完成；交付与限制见[报告](../reports/2026-11-10-legal-workbench-integration.md)。

## 目标与交付

把用户提供的五类业务、六步核心流程、Agent 执行/律师复核/知识复用三个特点，整理为九章节 SRS、V2.1 设计包、开发任务和可操作 HTML 原型。新建独立项目 `legal-agent-workbench-mvp`，不覆盖已有 personagent，也不改部署服务。

## 默认范围

五类业务均保留。默认单律师中文桌面体验、多客户隔离；生产架构设计保留认证、文件、AI、异步任务与检索/Word适配边界。法律条文和案例仅用明确标注的示例，真实法律有效性留在产品正式接入验收。原型需演示创建事项、Agent计划/结果、依据查看、律师编辑/退回/批准、交付、归档、客户知识复用、合同起草/对比/修订。

## 调用与最小实现

1. 复用 `ReqSessionStore` 与 `execute_clarification_turn`，按已授权默认值一次定稿；失败时最多定向修复三轮，保留审计及原始回复。
2. 调用 `validate_requirement_spec` 与 `handoff_srs_to_pipeline`，在独立根目录生成 S1 基线/S2 运行，使用既有项目登记与注册表，不改常驻配置。
3. 复用 Controller 的 S2/S3 流转与输入快照；本测试的调用适配器让只读模型返回文件映射，由程序校验路径后写入本轮输出目录。补充 V2.1 设计包与 HTML 原型属于用户本轮授权，不修改旧模板或旧运行。
4. 从本次需求独立列出功能/风险，调用 designsys 分类及规则选择，要求 S2 遵循程序生成的计划与全部适用规则；调用 validate_pack 校验，另检查当前模块未覆盖的 A02/A03/A06、需求映射和版本/引用。
5. S3 使用不同模型审查同一需求、快照与完整包；程序检查与浏览器实测共同决定本次测试结果，不用模型自报 PASS 代替实测。

该脚本是一次显式真实调用的集成入口，不将临时适配伪称平台已全面支持 V2.1。收费调用只在显式运行时触发；不修改 autoloop 内核、模型默认配置、机器人或对外发消息。

整合中已复现的必要修复：S2 input.md 以 `---` 开头，经共享 Claude argv 构造器传入时被 CLI 当成选项，模型未执行即退出。共享构造器应把所有选项放在前面、用 `--` 分隔后传入完整原文；不修改或截断提示词。调用方为 agent_runner（service 与本测试共用），补前导短横线和续接模式回归测试后重试，旧失败记录保留。

## 验收与证据

- SRS 通过现有校验且五业务/流程/特点逐项覆盖；交接身份一致。
- V2.1 固定文件、适用产物、规则和开发任务齐备；记录需求、资产版本和哈希，不以当前验证器的局部检查代表全部规范通过。
- 原型所有主要页面可访问，五业务可操作，核心六步链路与拒绝路径通过浏览器验证，截图与日志留存。
- 记录实际调用方式、请求模型 ID、可核实模型证据、耗时、返修轮次和限制；完成后写报告、更新 next/changelog 并本地提交。本轮后续用户已明确要求推送，允许推送当前开发分支；不含合并main或部署。
