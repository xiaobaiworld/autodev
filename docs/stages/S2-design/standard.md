# S2 设计：工作规范与完成条件

日期：2026-11-09。状态：从阶段机器人设计第 8 节整理而来；已接受方向与实现状态分别标明。返回 [S2 入口](README.md)，具体文件契约见 [contract.md](contract.md)。

## 1. 按任务设计，先核对资产

1. 对照需求原文、上游结论与同一份项目快照确认目标、约束和验收；关键歧义不能靠设计者猜。
2. 核对已有架构、接口、组件、工具与验证证据，说明可复用范围；只有实质冲突才建议改动，并记录取舍。
3. 编写方案与开发计划，让每个关键要求对应到设计、接口/页面、开发任务和验收。接口说明包含调用方、输入输出、错误、权限及兼容边界。
4. 有界面时设计关键页面、操作和状态；无界面时设计其真实使用入口，不能只写“不适用”便省略使用流程。
5. 交付前检查文件、引用、身份与需求覆盖；S3 返修逐项回应，不推倒无关内容。未决业务决定或重大冲突交人处理。

这套工作顺序沿用既有设计方向；具体程序强制项只以当前模板和实现为准，不能把建议清单写成所有条目已被自动验证。

## 2. 工具、模型与人的分工

| 工作 | 程序或工具负责 | Agent 或人负责 |
| --- | --- | --- |
| 输入与资产核对 | 路径、快照、文件与已有接口/证据检索 | 判断业务完整性、适用性及冲突 |
| 设计与计划 | 文件读写、适用模板与规则计算 | 架构、交互、取舍及任务拆分 |
| 原型 | 复用目标项目资产、本地预览、截图及关键操作检查 | 使用流程、体验判断和意见修订 |
| 预检与审核 | 文件/引用/规则检查、记录与轮次控制 | 语义覆盖、风险及无法程序判断的问题 |
| 交付 | 关联需求、版本、审查与证据 | 回应问题、处理业务取舍 |

当前已有快照、S2/S3 派发、返修、完成标记和记录；原型构建/交互检查、完整版本管理及设计讨论后端尚未接入。先查 [工具手册](../../TOOLS.md)，不以“工具优先”为由新建一套编排平台。

## 3. 原型与展示

优先复用目标项目已有 UI 和组件；无现有载体时可用本地 HTML 演示核心交互。示例数据必须匿名，模拟行为要明确标注。静态截图只证明所见外观，不能证明点击流程、文件处理或后台执行已通过。

飞书与 Web 只是身份接入和呈现渠道。同一任务应消费同一份产物；本机预览地址不能直接当作手机可访问链接，也不因此自动开放公网服务。渠道独立边界仍由 [平台设计](../../design/2026-11-08-stage-bots-design.md) 维护。

## 4. 完成条件与人工决定

当前旧模板的机械完成条件是约定文件和 `done.json` 校验通过，然后进入 S3。目标设计完成还应满足：输入基线明确、适用产物齐备、引用与版本一致、关键需求有验收映射、无阻塞性未决问题，并有适用的审查或如实记录的降级/免审依据。

目标中的人工确认以 [采用对照第 6 节](../../design/2026-11-09-v21-mapping.md#6-人工确认的位置用户确认的第-2-点) 为准：一般简单设计不增加人工定稿；复杂或无法程序判定的事项才可能触发。D2 默认值、模型建议阈值及冲突处理尚待确认，本次不代替用户定案。

旧 v0.1 中“有 UI 原型就必须人工确认”的表格已受 D026 调整，保留在 [历史原文](../../archive/2026-11-09-design-bot-work-instructions-v01.md)，不能作为当前一律执行的门槛。

需要人工确认时，确认应绑定所展示版本；修订后重新判断适用的审查和确认，旧意见不得自动覆盖新稿。这是目标约束，当前尚无完整自动失效机制。业务歧义、重大冲突、审核超限及既有发布/高影响操作关口继续适用。

## 5. 验证与后续补齐

审查规范见 [S3 standard](../S3-design-review/standard.md)；V2.1 检查能力见 [执行资产入口](../../../design-system/README.md)。校验器失败与自身出错应分别记录，未执行的检查写“未验证”，结构通过不能当作设计正确。

本轮不新建空的文档模板或示例。当前机器任务模板已在 `templates/pipeline/`；V2.1 产物结构已在 Schema。将来有真实设计任务暴露稳定复用内容时，再按主规范增加模板或匿名实例，避免维护第二套字段定义。
