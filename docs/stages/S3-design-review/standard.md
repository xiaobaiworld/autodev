# S3 设计审查：规范与分级放行

日期：2026-11-09。状态：整合阶段机器人设计原第 8.6 节；D019 是已接受原则，现有程序尚未完整适配。返回 [S3 入口](README.md)，当前执行协议见 [contract.md](contract.md)。

## 1. 审查什么

逐条对照需求原文，核对方案、计划与原型的位置；检查是否遗漏或改写要求，是否与项目事实冲突。检查资产复用证据、接口的输入输出/错误/权限/兼容边界、任务依赖与验收映射，以及有 GUI 时关键操作和状态覆盖。无 GUI 仍需核对实际使用入口。

只报会造成错误、重要信息缺失或不满足验收的问题，不报纯风格偏好。发现项应说明位置、影响、预期修复与证据；PASS 不得带 critical/high。未解决的实质阻塞不能因审查者不可用而自动消失。

## 2. 分级审查原则（D019）

以下来自 [D019](../../DECISIONS.md#d019-设计审查分级优先独立审核允许降级与简单复用免审)，是目标策略，不是当前模板已有的额外 verdict：

| 情况或可用能力 | 处理方向 | 必须如实记录 |
| --- | --- | --- |
| 简单任务且有适用的已验证资产 | 复用与必要差异说明，可免额外模型审核 | 对象、证据、适用范围、免审原因 |
| 正常任务，有不同 Agent 和跨厂商模型 | 优先独立审核 | 作者/审核者、模型、版本、结论 |
| 无上述组合，但有不同模型 | 同执行器切换模型或同厂商不同模型审核 | 实际模型、结果与独立性条件 |
| 只有一个 Agent/模型，或备用不可用 | 用现有模型和适用工具检查后降级放行，不为此额外强制人工批准 | 单模型检查、工具结果、降级原因与未覆盖检查 |

不为凑数量重复工作，同一模型多跑一次不算两个独立模型。请求模型 ID 与实际可核实身份要区分。简单复用至少要核对输入输出、接口、约束和环境以及已有验证证据；“做过类似的”不构成充分依据，有实质变化回正常设计路径。

工具能验证已知契约、文件与引用，不能仅用哈希证明业务等价。Agent 可提出分级建议，最终流转由程序按明确条件决定（D004）。当前复用判据、放行记录协议、模型尝试/超时预算仍待实施设计，不能无限重试以满足优选组合。

## 3. 程序检查、模型判断与人工决定

V2.1 的目标验证层级、统一结果契约与确定性优先规则见 [主规范](../../Agent自动化设计阶段规范_V2.1.md)；现有模块能力和限制见 [design-system](../../../design-system/README.md)。工具结果必须区分 passed、failed、error、not_applicable，不能把错误或未执行包装为通过。

独立审核通过、单模型降级和复用免审应分别留痕。后两者不得伪造 PASS 审核证据；现有模板只有 PASS/REWORK/BLOCK，适配时需要同时修改策略、记录和消费者，保留旧严格路径回归，不改 autoloop 内核。

人工确认以 [V2.1 采用对照](../../design/2026-11-09-v21-mapping.md) 的现行方向为准；有 UI 不自动增加人工门槛，复杂/高风险或无法判定的决定才可能需要。D2 默认与模型判断细节仍待确认。原有高影响操作、业务冲突与超限处理不因免模型审核而取消。

## 4. 当前缺口与证据边界

当前程序仍强制作者/审核者跨厂商，分级放行尚未落地；V2.1 四层验证、结构化包版本绑定、原型构建/交互/截图审查未接入。`ready_for_coding` 的独立模块返回值不能替代整条设计流程的真实验收。

规则或 Schema 的单元测试证明其已覆盖用例的行为；不证明真实需求特征识别正确、专业业务设计正确或生产环境可用。阶段文档本次只核对源码和路径，运行证据按 [项目索引](../../INDEX.md) 定位，未复跑的历史实验不改写为新验证。
