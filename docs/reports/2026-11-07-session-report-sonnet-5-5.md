9. **S7、S8、S9**：程序打候选和正式标签；验收；正式发布前停下等人批准。

## 5. 不能证明什么（同样重要）

- **没有任何一条优化被证明有效。** 所有真实对比都是单次对单次，而同一个需求的返工轮数波动很大（设计审查 1 到 3 轮都见过）。O001 的第一次对比总量降了 46%，但那主要是返工轮数不同，单步只降 4.6%。每条记录里都写了"样本不足"。
- **S7U 在真实 Codex 代码上跑过一次，结果不能用**：第一次判 FAIL 是我的使用脚本写错了（见 6.1），中途改过规则，不是干净样本。S7U 对真实代码"能不能抓到真问题"，目前**没有证据**。
- **S8 验收者没有亲手运行过代码。** R010 的验收报告自己承认了（A2）。S7U 是为这个补的，但补完之后的 S8 是否更可靠，没有证据。
- **Claude 审查者是否真的遵守"只读"**：程序只能发现它改了，不能阻止它改。R008、R010 里它没改，两次样本。
- **agy 没验证过**（实际模型、用量）。S8 验收者因此先绑了 Claude（D015），S6 和 S8 同厂商，独立性比原设计弱。
- **接真实项目（personagent）没做**：S7、S9 只在演示项目的本地 git 里测过，没有推送、没有部署。S5 和 S7U 执行 Agent 写的代码，在 Agent 沙箱之外，隔离挡不住网络和对其他绝对路径的写入。

## 6. 过程中我自己犯的错（如实记录）

这些是驾驶员的失误，换 Agent 重做时最值得比较：

| 错误 | 怎么发现的 | 后果 |
| --- | --- | --- |
| 一次 Edit 把 `controller.py` 的 `if self.on_finish:` 误改成 `if False:` | 我自己发现 | 每步记录会静默失效；当场改回并用 grep 确认 |
| 写 `pipeline.py` 时内容被截断，文件一度是坏的 | 读文件发现 | 补全；之后写大文件改成小段 Edit |
| 在"收窄红线"时一次替换把 `SetupError` 类定义吃掉了 | 我 grep 发现 | 立刻补回；还发现 `return` 之后留着一大段旧代码，删掉 |
| 好几次把"和编辑并行跑出来的测试通过"当成通过 | 数字没变（9 个还是 9 个）时起疑 | 之后改成：编辑落盘后单独再跑一次，才算数 |
| 我加的红线"修改权限"，让 Codex 把 `chmod +x` 当成改权限而 BLOCK | R009 的 S4 报告 | 收窄红线。**这是我的措辞造成的，不是 Codex 的错** |
| 写测试的写法错误：`lambda … or {…}` 在 `write_text` 返回字符数时短路 | 测试报 `int not subscriptable` | 改成正经函数（同样的坑踩了两次） |
| 好几处文档里的计数、状态过时（"17 份"、"进行中"） | 自己复查 | 改成实测数字 |

另外两个**环境问题**不是我的错但耗了不少时间：Bash 工具经常被安全分类器拦（它依赖的模型时好时坏），复合命令不命中白名单；`git push` 偶发 SSL 断开，重试即好。

### 6.1 写这份报告时发现的一个新错（R20261107-001，第一次带 S7U 的真实运行）

S7U 在真实 Codex 写的 `bin/todo` 上第一次判了 FAIL（`usage.log` 第 4 行：`No such file or directory: …/scratch/data/tmpXXXX`），退回 S4 第 2 轮。读日志后发现：**错的是我写的使用脚本，不是 Codex 的代码。** 我把 `TODO_FILE` 指向了不存在的 `scratch/data/` 子目录，而需求原文只说"路径可用环境变量 `TODO_FILE` 覆盖"，没有要求程序替用户建父目录。Codex 的代码没违反需求，却被我的脚本判了失败，白白多跑了一轮。

- 为什么我之前没发现：假 Agent 联机验证里的 `bin/todo` 恰好会自己建父目录，所以脚本里这个错误被掩盖了。
- 教训：**使用脚本本身要被验证，而且要对着会按需求字面做事的真实 Agent 验证，不能只对着我自己写的假 Agent。**
- 已改：数据文件改到草稿目录根下（`{scratch}/todo.json`）。
- 对这次运行的影响：模板每步重新读取，所以我中途的修改会作用于之后的步骤。**R20261107-001 的 S7U 结果被我中途改过规则，不是干净样本，不进任何结论。**
